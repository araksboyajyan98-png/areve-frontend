# Фронтенд — архитектура

Источник правил: `skeleton/01-frontend.md`, `03-i18n.md`, `04-configs.md`,
`05-arch-checks.md`. Этот файл — рабочая копия для проекта **Areve**; при
расхождении с новым решением правится он, а не скелет.

Проект: лендинг центра детской занятости **Արևէ** (Areve), город Абовян,
дети 1,5–6 лет. Структура сайта — раздел 13.

---

| Что | Чем |
|---|---|
| Язык | TypeScript (strict) |

| Стили | Tailwind CSS 3 + CSS-переменные темы |

## 2. Архитектура — Feature-Sliced Design

Путь до файла отвечает на три вопроса: **слой** (кто кому может быть известен),
**слайс** (о чём это), **сегмент** (что это за код).

### Дерево

```
areve-frontend/
  docs/                         architecture.md, project-plan.md, UI-fixes.md
  tests/                        договор с бэкендом
  skeleton/                     правила архитектуры
  index.html  vite.config.ts  tsconfig*.json  eslint.config.js
  tailwind.config.js  postcss.config.js  .env.example
  tools/check-fsd.cjs           машинная проверка архитектуры
  src/
    main.tsx                    точка входа
    app/                        сборка приложения
      index.tsx                 провайдеры + роутер
      Router.tsx                все маршруты
      providers/                ThemeProvider
      layouts/                  AppLayout
      styles/App.css            @tailwind + переменные темы
    pages/                      экраны
    widgets/                    крупные самостоятельные блоки
    features/                   действия пользователя (Theme, Language, …)
    entities/                   предметные сущности
    shared/                     ничего не знает о слоях выше
      api/                      axios-клиент
      config/                   чтение VITE_* переменных
      lib/                      cn, getErrorMessage
      i18n/                     переводы
      ui/                       базовые компоненты
      mocks/                    мок-адаптер axios
```

### Слои

Порядок снизу вверх: `shared` → `entities` → `features` → `widgets` → `pages` → `app`.
**Импорт разрешён только вниз.** `main.tsx` стоит над `app` — ей можно всё.

### Слайсы

- Слайс в `entities`, `features`, `widgets`, `pages` — каталог с `index.ts` (публичный API).
- **К чужому слайсу — только через его `index.ts`.**
- **Внутри своего слайса — относительные пути**, не через свой `index.ts` (круг).
- **Слайсы одного слоя друг друга не импортируют.** Исключение — сущности:
  одна отдаёт другой API через `@x`: `entities/A/@x/b.ts` для слайса `B`.

### Сегменты

| Сегмент | Что кладём |
|---|---|
| `ui/` | компоненты (`.tsx`) |
| `model/` | хуки (`use*`), сторы, типы |
| `api/` | обращения к серверу |
| `zod/` | схемы форм |
| `lib/` | помощники без разметки |
| `config/` | константы |
| `@x/` | только у сущностей |

Хук вне `model/`, компонент вне `ui/`, файл в корне слайса (кроме `index.ts`) — ошибка.

### `shared`

Слайсов нет, только сегменты `api`, `lib`, `ui`, `config`, `mocks`, `i18n`;
между собой обращаются напрямую. В `ui/` — только компоненты; помощники общего
назначения (`cn`) — в `lib/`, и `ui/index.ts` их не реэкспортирует.

### Пути

Между слайсами и слоями — псевдоним `@/…`, никаких `../../..`. Псевдоним объявлен
**дважды и должен совпадать**: `vite.config.ts` и `tsconfig.app.json`.

### Страницы и каркасы

- Экран: `pages/<Page>/ui/<Page>Page.tsx` + `pages/<Page>/index.ts`.
  Группировка допустима: `pages/<Group>/<Page>/…` (у папки группы нет `index.ts`).
- У страницы только сегмент `ui/`.
- `Router.tsx` импортирует только `@/pages/<Page>`.
- Каркасы страниц живут в `app/layouts` — они собирают виджеты и страницы.
- Статичный сегмент маршрута объявляется **до** параметрического:
  `/items/new` раньше `/items/:id`.

### Мёртвый код

Файл, на который никто не ссылается, удаляется. `check:arch` находит файлы,
недостижимые от `main.tsx`.

## 4. Конфиг окружения

```ts
// src/shared/config/index.ts
export const config = {
  apiUrl: import.meta.env.VITE_API_URL ?? "http://localhost:5001/api",
  useMocks: import.meta.env.VITE_USE_MOCKS === "true",
} as const;
```

`VITE_*` подставляются **на сборке**, а не в рантайме. Новая переменная —
сразу в `.env.example` и в `src/vite-env.d.ts`.

---

## 5. HTTP-клиент

`src/shared/api/client.ts` — один экземпляр axios с `baseURL: config.apiUrl`.

Запросы предметной области живут в сегменте `api/` своей сущности:
`entities/<Entity>/api/<entity>Api.ts`. Компоненты в axios не ходят.

---

## 6. Ошибки

Сервер отдаёт конверт `{ error: { code, message, details? } }`. Текст для
пользователя собирает фронтенд **по `code`**, а не по серверному тексту.

- `shared/lib/getErrorMessage.ts` — код → перевод; `fallback` передаётся
  **ключом перевода**, а не строкой.
- Незнакомый код: серверный `message` показывается только на 4xx (в 5xx может
  попасть содержимое исключения).
- `getErrorCode()` — когда нужно отличить случай, а не показать текст.

Каждый код ошибки бэкенда обязан иметь перевод в разделе `errors`.

---

## 7. Данные

Хуки на `useState + useEffect`, флаг `cancelled`, чтобы не писать в
размонтированный компонент. Шаблон — `01-frontend.md`, раздел 8.

- Независимые запросы одного экрана — `Promise.allSettled`.
- Состояние, зависящее от параметра, **выводится из данных**, а не выставляется
  `setState` в теле эффекта.
- Понадобятся кэш и ретраи — подключается TanStack Query (сейчас не стоит).

---

## 8. Формы

react-hook-form + zod, схема в сегменте `zod/`.

**Схема хранит ключ перевода, а не текст**: она создаётся один раз при загрузке
модуля, и текст застыл бы на языке того момента. Ключ превращает в текст
`useFieldError()` на каждой отрисовке.

---

## 9. Тема

Тема — атрибут `data-theme="light" | "dark"` на `<html>`.

- Цвета — CSS-переменные в `app/styles/App.css`, формат `"R G B"` без `rgb()`
  (иначе не работает `bg-bg/50`).
- Компоненты берут цвета через Tailwind и **о теме не знают**.
- Стор — `features/Theme`; **к документу применяет только** `app/providers/ThemeProvider`.
- `index.html` выставляет атрибут до первой отрисовки — иначе мигает неверная тема.
- Новый цвет добавляется **в обе темы** и в `tailwind.config.js`.

---

## 10. Переводы

Полные правила — `skeleton/03-i18n.md`. Коротко:

1. Приложение не импортирует `i18next` напрямую — только `@/shared/i18n`.
2. Словари — TypeScript, по файлу на раздел, все языки рядом.
3. **Пропущенный перевод — ошибка компиляции** (`defineSection` + `SOURCE_LOCALE`).
4. Всё, что создаётся при загрузке модуля, хранит ключ, а не текст.
5. Вне компонента — `translate`, в компоненте — `useT`.
6. Выбор языка: сохранённый в браузере → язык браузера → по умолчанию.
7. Смена языка меняет `<html lang>`.
8. Сервер тексты интерфейса не переводит.

---

## 11. Мок-режим

`VITE_USE_MOCKS=true` подменяет **транспорт axios целиком**
(`shared/mocks/adapter.ts`). В компонентах нет ни одного `if (useMocks)`.

Сравнение идёт с литералом `import.meta.env.VITE_USE_MOCKS === "true"`, а не через
`config`: Vite подставляет значение на сборке и вырезает ветку вместе с
динамическим импортом из продакшен-бандла.

`shared/mocks` не импортирует типы из `entities` — `shared` не зависит от слоёв выше.

---

## 12. Проверка архитектуры

`npm run check:arch` → `tools/check-fsd.cjs` (скрипт целиком — `05-arch-checks.md`).

Ловит: файлы вне слоёв; файл в корне слайса; неизвестный сегмент; хук вне
`model/`; компонент вне `ui/`; `@x` не у сущности; у страниц не только `ui/`;
импорт вверх по слоям; импорт между слайсами одного слоя; обход чужого `index.ts`;
`../../..` вместо `@/`; относительный путь за пределы слайса; свой слайс через
собственный `index`; реэкспорт `cn` из `shared/ui`; мёртвый код.

**Зелёный результат обязателен для каждой правки.** Дополнительно на pre-commit:
`lint-staged` (eslint --fix) и `tsc -b --noEmit`.

## 13. Структура проекта Areve

### Что это за сайт

Одностраничный лендинг центра детской занятости «Արևէ» (`արև` — солнце,
`է` — сущность) в городе Абовян. Дети 1,5–6 лет, полный и неполный день.
Задача сайта одна: **родитель понимает, подходит ли ему центр, и оставляет заявку.**

Сайт ничего не показывает по логину, ничего не считает и почти ничего не грузит
с сервера. Единственный запрос к бэкенду — отправка формы.

### Маршруты

| Путь | Страница |
|---|---|
| `/` | `pages/Home` — вся прокрутка с якорями |
| `*` | `Navigate to="/" replace` |

Вторая страница появится, только если понадобится юридический текст
(политика обработки персональных данных) — тогда `/privacy`.

Навигация внутри страницы — якоря `#hero`, `#about`, `#routine`, `#terms`,
`#testimonials`, `#nutrition`, `#contact`, как в существующем лендинге.

### Слои

```
pages/
  Home/                 ui/HomePage.tsx — собирает виджеты по порядку

widgets/
  Header/               логотип, меню, бургер на узком экране
  Hero/                 заголовок, «1.5–6 տարեկան», две кнопки
  About/                текст + карусель фотографий
  Values/               4 карточки ценностей
  Adaptation/           блок «3 дня бесплатной адаптации»
  Routine/              6 карточек распорядка дня
  Terms/                2 тарифа: полдня 08:00–13:00, полный день 08:00–18:00
  Testimonials/         3 отзыва, карусель на узком экране
  Nutrition/            галерея + пример меню на день
  Contact/              контакты, карта, форма
  Footer/               логотип, ссылки, копирайт

features/
  ContactForm/          единственное действие пользователя: оставить заявку
  Theme/                переключение темы (из скелета)

entities/
  Lead/                 заявка: тип + api/leadApi.ts

shared/
  ui/Carousel/          один механизм карусели на три места применения
  ui/…                  Button, Section, Card
  lib/, api/, config/, i18n/, mocks/
```

### Одно важное решение: контент — не сущности

Ценности, распорядок, тарифы, отзывы, меню **не приходят с сервера** и не
становятся `entities`. Это тексты: они живут в словарях `shared/i18n`, а порядок
и иконки — в сегменте `config/` своего виджета.

Настоящая сущность здесь одна — **`Lead`** (заявка), потому что она уходит на сервер.

### Ловушка, о которой помнить

Списки карточек создаются при загрузке модуля. По правилу 4 из `03-i18n.md`
**они хранят ключи перевода, а не текст** — иначе тексты застынут на языке
того момента и не сменятся вместе с языком:

```ts
// widgets/Values/config/values.ts
export const VALUES = [
  { icon: "heart",  title: "values.individual.title",  text: "values.individual.text" },
  { icon: "shield", title: "values.safety.title",      text: "values.safety.text" },
  // …
] as const;
```

Это касается всех пяти списков: ценности (4), распорядок (6), тарифы (2),
отзывы (3), меню (4).

### Языки

**Решено 18.09.2026: сайт только на армянском.**

```ts
export const LOCALES = ["hy"] as const;
export const SOURCE_LOCALE = "hy";
export const DEFAULT_LOCALE: Locale = "hy";
```

Следствия:

- `features/Language` не нужен — переключать нечего.
- `<html lang="hy">` задаётся в разметке и не меняется.

`shared/i18n` при этом **остаётся**, хотя язык один. Причины две: тексты не
разъезжаются по компонентам, а набор ключей проверяет компилятор. Если русский
когда-нибудь понадобится, он добавляется одной строкой в `LOCALES`, и `tsc`
сам покажет каждый непереведённый ключ — без этой машинерии пришлось бы искать
их глазами по всему коду.

### Дизайн

Палитра и шрифты берутся из существующего лендинга:

```
--cream #FAF7EF   --cream-deep #EEE4CE   --white #FFFDF8
--ink #37322B     --ink-soft #6E6455     --line #DED2B7
--orange #C97A48  --orange-deep #A85E35
--sage #8B9473    --sage-deep #69745A
радиус карточек 20px, контейнер 1120px
```

Шрифты: `Noto Serif Armenian` (заголовки), `Noto Sans Armenian` (текст).

**Требует решения:** тёмная тема. Палитра тёплая кремовая, тёмного варианта у
неё нет, и для лендинга детского центра тёмная тема — не самоочевидная вещь.
Механизм из скелета оставляем (он ничего не стоит), но пока задаём обе темы
одинаково светлыми и решаем отдельно.

### Изображения

В лендинге **10 картинок вшиты как base64** — отсюда 453 КБ HTML. В проекте они
становятся файлами: логотип — SVG, фотографии — `.webp` с размерами под
`srcset`, `loading="lazy"` на всём, кроме hero.

### Чего на фронтенде нет и не планируется

Авторизации, личного кабинета, оплаты, календаря записи. Если понадобится
админка для просмотра заявок — это отдельный разговор: в скелете авторизации нет.
